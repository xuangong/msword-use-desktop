# Skills + Slash Commands 实施调研与方案

> 暂存：v0.5 准备文档。基于 2025-12 调研。

## TL;DR

直接采用 **Anthropic Agent Skills 开放标准**（已捐赠给 Linux Foundation 旗下 Agentic AI Foundation，2025-10 发布、2025-12 开源），不发明新 schema。MVP 范围 2-3 周，3 个内置 skill：`polish` / `translate` / `gongwen-lint`。

## 1. 为什么是这个方向

**业内共识（2025-2026）**：
- **markdown 是 skill 的事实标准** —— Claude Code、Cursor、Manus、Goose 都走这条路；非工程师可写、git diff 可读、LLM 直接消化
- **双轨制** = 显式 `/slash` + 隐式语义匹配。生产级系统（Claude Code / Cursor / Manus）几乎全部如此
- **渐进披露**（progressive disclosure）三级：metadata 注入 → 命中后加载正文 → 执行时按需读 references/scripts。研究表明 30K 精调上下文常优于 150K 塞满
- **skills + MCP 双栈互补**：MCP 解决"agent 怎么连数据/服务"，skills 解决"agent 怎么思考/做决策"

**关键判断**：msword-use-desktop 的差异化**不在 agent 框架多牛，而在为中文 Office 写作场景预置的高质量 SKILL.md 集合**。架构标准化 + 内容做厚 = 赢。

## 2. Anthropic Agent Skills 标准（基线）

### 目录结构
```
.claude/skills/<skill-name>/
  SKILL.md          # 必须
  scripts/          # 可执行脚本（bash/python/node）
  references/       # 按需加载的长文档
  assets/           # 模板、字体、数据
~/.claude/skills/   # 用户级，跨项目
```

### SKILL.md frontmatter（最小集只需 2 字段）
```yaml
---
name: gongwen-lint              # 仅小写字母/数字/连字符，≤64 字符，须等于目录名
description: 公文审校。当用户写作或修改党政机关公文、通知、报告、请示时使用，按 GB/T 9704 排版规范检查标题层级、行文用语、附件格式。
allowed-tools: Read, Edit       # 可选，工具白名单
model: claude-haiku-4-5         # 可选
---

# 操作步骤（自然语言 + 可选 ${arg} 模板）
1. ...
2. ...
```

`description` 上限 1024 字符，是触发匹配的核心信号。

### Slash command（旧式，仍并存）
- `.claude/commands/<name>.md`
- 参数：`$ARGUMENTS` 整串、`$1`/`$2` 位置、`${1:-default}` 默认值
- `!` 内联 bash、`@` 内联文件
- 逐渐被 skills 吞并

### 渐进披露
1. 启动只把 `name + description` 注入系统提示（约 100 token）
2. LLM 判断相关后，加载完整 SKILL.md 正文（建议 <5k token，<500 行）
3. 执行中按需读 `scripts/references/assets/`

### Subagent vs Skill（容易混）
- **Skill**：共享主上下文，是"食谱/手册"
- **Subagent**：独立上下文窗口，靠 Task tool 委派，适合"冷视角的代码评审"

## 3. 横向对比

| 系统 | 单元 | 触发 | 参数 | 备注 |
|---|---|---|---|---|
| **Claude Code** | Markdown 文件夹 | 隐式语义 + `/`显式 | `$ARGUMENTS`/`$1` | 三级渐进披露，开放标准 |
| **Cursor** | `.mdc` rules + `.md` commands | 4 种模式：always/auto/intelligent/manual | `@rule-name` | 2025 取消 Custom Modes 统一到 slash |
| **Continue.dev** | Markdown + `invokable: true` | `/` 触发 | freeform | 旧 slashCommands 数组弃用 |
| **Aider** | Python `cmd_*` 方法 | 严格 `/` 或 `!` | 位置式 | 43 条命令，无用户扩展 |
| **Goose** (Block) | YAML/JSON Recipes + MCP Extensions | slash + 平台 | Jinja `{{var}}` | 已支持 skills 标准 |
| **Manus** | 完全采纳 Agent Skills 标准 | `/SKILL_NAME` + 隐式 | 同 Anthropic | 五层架构：Registry/Utilities/Skills/Meta-skills/DAG |
| **CrewAI** | Python `@tool` 装饰器 | 无 slash，全靠 LLM 选择 | Pydantic schema | 偏"工具"非"技能" |
| **smolagents** | `Tool` 子类，HF Hub 远程 | `load_tool()` | typed inputs | hub 即 skill marketplace |
| **GPT Custom Actions** | OpenAPI schema | 隐式函数调用 | OpenAPI 参数 | 无 slash |
| **MCP** | JSON-RPC server | 隐式工具调用 | JSON Schema | 与 skills **互补** |

## 4. 七个设计维度

| 维度 | 主流选择 | msword-use 选择 |
|---|---|---|
| 组合单元 | markdown ↑ vs 代码 vs 协议端点 | **markdown 文件夹** |
| 发现机制 | 文件系统扫描 ↑ vs manifest vs 远程 registry | **文件系统扫描**（最低摩擦） |
| 调用模式 | 仅显式 vs 仅隐式 vs **双轨制 ↑** | **双轨** |
| 参数解析 | freeform / 位置 / 命名 / typed schema | **slash 入口 freeform，工具调用 typed** |
| 工具范围 | per-skill `allowed-tools` 白名单 | **per-skill 白名单** |
| 上下文预算 | **渐进披露 ↑** vs 全量加载 | **渐进披露**（首版只做二级） |
| 作用域 | 项目本地 / 用户全局 / marketplace | **内置 + 用户级覆盖** |

## 5. msword-use-desktop 实施方案

### 5.1 目录结构
```
~/.msword-use/             # 用户级，跨项目
  skills/<name>/SKILL.md
apps/agent/skills/         # 内置（随安装包发布）
  polish/SKILL.md
  translate/SKILL.md
  gongwen-lint/SKILL.md
apps/agent/src/skills/     # loader 代码
  loader.ts
  registry.ts
  types.ts
```

**复用 Anthropic 规范**（不发明新 schema）—— 用户从 Claude.ai/GitHub 拷的技能即插即用。

### 5.2 frontmatter 扩展（自有，向后兼容标准）

```yaml
---
# Anthropic 标准字段
name: gongwen-lint
description: 党政公文审校。当用户在 Word 中写作或编辑通知、请示、报告、纪要等公文时使用；按 GB/T 9704-2012 检查标题层级、文种用语、主送/抄送、附件、成文日期格式。
allowed-tools: [polish_text, observe.selection]
model: claude-sonnet-4-6        # 可选

# msword-use 私有扩展
trigger:
  slash: ["/lint", "/公文"]
  keywords: ["公文", "请示", "通知 排版"]
arguments:
  - name: variant
    type: enum
    values: [党委, 政府, 企业]
    default: 政府
locale: zh-CN
---
```

**为什么加 `trigger.slash` + `trigger.keywords`**：description 语义匹配在小数据集下不稳，硬关键字给中文用户兜底。**Anthropic 标准只有 description 一字段做匹配，对中文场景不够。**

### 5.3 调度器架构

**核心技巧**：把 N 个 skill 折叠成**一个** `invoke_skill` meta-tool 暴露给 LLM。
- 避免 200K 上下文被工具 schema 撑爆
- 符合 Anthropic 渐进披露原则
- N 增长不影响首轮 prompt 大小

```typescript
// 启动时
const skills = await loadSkillsFromDirs([builtInDir, userDir]);
const skillIndex = skills.map(s => `- ${s.name}: ${s.description}`).join("\n");

const tools = [
  ...coreTools,                     // polish_text, observe.selection 等原子能力
  {
    name: "invoke_skill",
    description: "调用一个已注册的 skill。可用 skill 见 <skills> 段。",
    input_schema: { skill_name: "string", args: "object" }
  }
];

async function runAgentTurn(userMsg: string, target?: PinnedTarget) {
  // ① 显式 slash 短路
  const m = userMsg.match(/^\/(\S+)\s*(.*)/);
  if (m) {
    const [, name, rest] = m;
    const skill = resolveSkillBySlash(skills, name);
    if (skill) {
      yield { kind: "skill_invoke", skill: skill.name, source: "slash", args: rest };
      return executeSkill(skill, parseArgs(skill, rest), target);
    }
  }

  // ② 否则 LLM 看到 skillIndex，自己决定要不要 invoke_skill
  return runLLMLoop({
    systemPrompt: BASE_PROMPT + `\n<skills>\n${skillIndex}\n</skills>`,
    tools,
    userMsg,
  });
}

async function executeSkill(skill, args, target) {
  // ③ 加载 SKILL.md 正文 + 该 skill 的 allowed-tools 子集
  const body = await fs.readFile(skill.path);
  const scoped = filterTools(coreTools, skill.allowedTools);
  return runLLMLoop({
    systemPrompt: BASE_PROMPT + body,
    tools: scoped,
    userMsg: renderArgs(args),
    target,
  });
}
```

**双触发统一**：
- 用户 `/lint 党委` → 短路直跑（skill_invoke source="slash"）
- 用户"帮我看下这份请示有没有问题" → LLM 在 skillIndex 中识别 `gongwen-lint` 描述 → 调 invoke_skill（skill_invoke source="llm"）

**两条路汇合到 `executeSkill`**，下游一致。

### 5.4 热更新

- Bun `fs.watch` 监听 skills 目录
- dev 模式保存 SKILL.md 即重载 registry
- 用户级覆盖项目级（同名 skill 时）

### 5.5 可观测（接入现有 DebugEvent）

新增 `skill_invoke` event kind：
```ts
{
  kind: "skill_invoke",
  skillName: string,
  source: "slash" | "llm",
  args: unknown,
  reason?: string  // 当 source=llm 时记录"LLM 选了这个 skill 的原因"
}
```

主窗口右栏 DebugPanel 加 filter 选项，让用户能看：
- 哪个 skill 被选了
- 为什么（slash 直跑 / LLM 自选）
- 子 LLM call 的完整 prompt（已通过 v0.4-debug 实现）

## 6. MVP 范围

### 第一阶段（2-3 周）

**做**：
- ✅ skills 目录扫描 + frontmatter 解析（gray-matter）
- ✅ `/slash` 短路调度
- ✅ LLM 隐式 `invoke_skill` 工具
- ✅ description 注入 system prompt（**不做**第三级 `references/`）
- ✅ skill_invoke debug event
- ✅ 三个内置 skill：

| Skill | 类型 | 价值 |
|---|---|---|
| **`polish`** | 包装现有 polish_text | 把已有逻辑迁到新框架，零新功能 |
| **`translate`** | 新建 translate_selection 工具 | slash `/translate en`/`/translate zh`，隐式触发"翻译" |
| **`gongwen-lint`** | 纯 prompt 驱动 + 现有 observe/edit 工具 | **无新工具仅靠 SKILL.md 也能扩展** —— 验证架构有效性的关键 demo |

`gongwen-lint` 是核心说服 demo —— 证明加 skill **不需要写代码**，只需要写 markdown。

**不做**：
- skill 之间的 DAG 编排（≥ 8 个 skill 时再上）
- 渐进披露第三级 `references/scripts/assets/`
- subagent / 隔离上下文（msword 单文档场景没必要）
- 远程 marketplace、版本管理、telemetry（git 同步够了）
- 自定义 schema —— **坚决采用 Anthropic 标准**

### 第二阶段（看反馈再说）
- references/ 文档懒加载
- skill 间组合（polish → lint → polish）
- 用户分享：README 教用户把社区 SKILL.md 放进 `~/.msword-use/skills/`
